3. Validate：结构验证

典型检查包括：

  • 是否存在SKILL.md；
  • YAML Frontmatter是否有效；
  • name和description是否存在；
  • 文件是否可读且编码正确；
  • 资源路径是否合法；
  • 是否超过平台的文件数量或大小限制。

结构验证只能证明Skill可被读取，不能证明它能正确触发、遵循流程或生成高质量结果。因此至少要区分：

4. Install / Upload：进入运行环境

本地文件系统可将Skill放在项目级或用户级Skill目录中，由宿主扫描。托管环境通常执行：

“安装”的实质是把Skill文件放到Agent可以访问且会扫描的位置，不一定意味着运行传统安装脚本。

5. Discovery：发现Skill

Discovery阶段通常只暴露元数据，不加载完整工作流和所有资源。这解释了为什么name和description至关重要：模型必须先根据封面决定是否打开这本书。

6. Trigger：触发判断

两种触发方式：

隐式触发

用户描述任务，模型根据description自动选择Skill。

显式触发

用户直接指定Skill名称。显式调用降低Discovery不确定性，但不自动保证执行质量。

触发通常是语义判断，而不是简单关键词匹配。它可能产生：

实际情况 是否触发 结果
应使用 使用 True Positive
不应使用 使用 False Positive
应使用 未使用 False Negative
不应使用 未使用 True Negative

7. Load：加载完整指令

13. Validate：验证结果

执行完成不等于任务完成。需要进行三层验证：

13.1 结构验证

报告是否包含Summary、Evidence、Root Cause、Confidence和Recommendations。

13.2 语义验证

结论是否由证据支持，建议是否针对根因，置信度是否与证据强度一致。

13.3 执行验证

18. 典型失败点

阶段 典型失败
Author 职责太大、流程含糊
Validate YAML错误、路径无效
Install 放错目录、上传失败
Discovery 没被扫描到
Trigger 漏触发或误触发
Load 文件不可读、指令冲突
Precondition 输入不足却继续分析
Resource loading 读错资料或加载过多
Execute 漏步骤、顺序错误
Tool call 参数错误、超时、权限不足
Validate 没检查结果质量
Output 不符合格式或缺乏证据
Version 更新后回归
Security 恶意Skill或资源注入

20. 本章总结

Skill同时具有管理生命周期和执行生命周期。管理生命周期负责创建、验证、安装、版本和发布；执行生命周期负责发现、触发、加载、前置检查、资源读取、工作流执行、工具调用、结果验证和输出。Skill可靠性不是由某个SKILL.md文件单独决定，而由整条链路共同决定。
