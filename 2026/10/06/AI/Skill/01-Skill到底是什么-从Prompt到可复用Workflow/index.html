2. Skill的准确含义

可以把Skill定义为：

Skill是一个按需加载的、可复用的Agent工作方法包。它用指令描述工作流程，并可携带参考资料、脚本、模板和其他资源。

OpenAI把Skill描述为包含SKILL.md的文件目录，用于编码流程和约定；除主指令外，还可以包含参考资料、脚本和资产。Anthropic的定义与此相近：Skill由元数据、指令以及可选脚本和模板构成，在任务相关时按需使用。

3. 为什么普通Prompt不够

假设我们经常要求Agent分析Linux性能问题：

这种一次性Prompt可以工作，但有几个工程问题。

3.1 难以稳定复用

每次都要重新说明检查顺序、证据标准、输出格式和失败行为，容易漏步骤，也容易产生不同版本。

3.2 只能低效携带大量文字

把它们全部复制进Prompt会快速占满上下文。

3.3 难以成为工程资产

散落在聊天记录中的Prompt不利于：

  • 代码审查
  • 版本管理
  • 团队共享
  • 自动测试
  • 回归评测
  • 权限和安全审计

Skill将工作方法文件化，使它更接近可维护的软件模块。

4. 从Prompt到Skill的演化

它们不是互相替代，而是作用范围不同：

形式 适合解决的问题
User Prompt 当前这一次具体要做什么
Prompt模板 重复生成相似内容
Skill 某类任务长期应该怎样完成
Script 确定性计算、解析和校验
Tool 对外执行一个动作
RAG/Reference 提供任务所需知识或事实

6. Skill为什么通常是目录

真实工作方法往往不止一段文字：

各部分职责如下：

部分 职责
SKILL.md 工作流主干：何时使用、按什么步骤做
references/ 背景知识、规范和领域规则
scripts/ 确定性、重复性操作
assets/ 输出模板、Schema、配置或素材

7. Skill不是Tool

OpenAI官方给出的边界是：MCP Server或Tool提供实时数据、认证、授权和动作；Skill规定什么时候调用、调用顺序、不完整结果如何处理，以及最终输出应包含什么。

Tool是“手”，Skill是“操作手册和工作方法”。

10. 什么任务值得做成Skill

适合做成Skill的任务通常具有以下特征：

  • 经常重复出现；
  • 存在明确但容易遗漏的步骤；
  • 输出需要保持一致；
  • 需要协调多个Tool；
  • 有领域规则或组织规范；
  • 可以定义完成标准；
  • 有必要进行测试和版本管理。

不一定需要Skill：

  • 一次性简单问答；
  • 一句话就能稳定描述的任务；
  • 没有固定流程的开放闲聊；
  • 单一确定性计算，这更适合函数或脚本；
  • 只有资料检索需求，这更接近RAG。

11. OpenAI与Claude的共同点和差异

共同点：

  • 都以目录作为基本单位；
  • 都要求SKILL.md；
  • 都依赖name和description进行发现；
  • 都支持指令、参考资料、脚本和模板；
  • 都强调按需加载；
  • 都把Skill定位为可复用工作流。

14. 本章总结

Prompt描述当前任务，Tool提供可调用动作，而Skill把一类任务的完成方法封装成可发现、按需加载、可复用的工作流。SKILL.md是流程主干，references提供知识，scripts承担确定性操作，assets提供模板和资源。Skill的真正价值不是让模型“知道更多”，而是让Agent在相似任务中以更稳定、可验证、可维护的方式做事。
