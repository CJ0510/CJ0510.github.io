1. 总体分层

一句话区分：

概念 一句话定义 回答的问题

5. Tool：可调用的具体动作

Tool通常具有明确名称、输入和输出：

Tool的典型特征：

  • 有明确名称；
  • 有参数或输入Schema；
  • 执行一个相对明确的动作；
  • 返回数据或产生副作用；
  • 可能成功、失败或超时；
  • 通常不负责完整业务流程。

7. RAG：为当前任务查找知识

RAG回答“完成当前任务需要哪些外部知识”。Skill回答“拿到这些知识后怎样完成任务”。Skill可以规定检索策略，但检索系统本身仍是独立能力。

references/与RAG

references/通常随Skill打包，版本固定、内容可审查；RAG通常从更大的外部语料库动态检索，可能产生召回和排序误差。

8. Memory：跨任务保留信息

Memory可以保存：

  • 用户偏好；
  • 项目约定；
  • 历史决策；
  • 已知问题；
  • 上一次任务进度；
  • 执行中总结出的经验。

10. 三个常见架构错误

10.1 把Skill写成Tool说明书

仅罗列query_metrics、query_logs和get_alert没有描述如何完成任务。好的Skill应规定收集顺序、证据标准和终止条件。

10.2 把MCP当成业务流程

MCP Server提供全部工具，不等于Agent知道调用顺序、完成标准和失败行为。MCP解决接入问题，不自动解决Workflow设计。

10.3 把Memory当成可信知识库

Memory可能包含错误或被Prompt Injection污染。必须考虑来源、所有者、写权限、过期策略、纠错方式和可信等级。

11. Skill不是确定性工作流引擎

即使SKILL.md写了A、B、C三个步骤，实际执行者仍是语言模型，可能误解、漏步、提前终止或输出不符合Schema。

关键约束应下沉到：

  • 程序控制流；
  • Tool参数Schema；
  • 权限系统；
  • 状态机；
  • 审批节点；
  • 确定性验证脚本；
  • 服务端业务规则。

例如“转账前必须取得用户确认”不能只写在Skill里，更应在Tool或服务端强制要求有效的approval_token。

15. 本章总结

Prompt表达当前要求，Skill封装可复用工作方法，Agent负责围绕目标作出决策，Tool提供实际动作，MCP标准化外部能力的接入，RAG检索当前需要的知识，Memory保留跨任务状态。Skill位于目标和动作之间，但不是强确定性程序，因此安全约束仍应在代码、权限或工具层强制。
