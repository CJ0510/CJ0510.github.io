第7章：Buddy System整体设计——Linux到底怎么管理空闲物理页？

但知道系统中有哪些物理页，还不等于知道如何分配物理页。内核还必须持续回答下面几个问题：

解决这些问题的核心机制，就是Buddy System（伙伴系统）。

Buddy System把连续物理页按2^order的大小组织起来。分配时可以把较大的空闲块逐级拆分，释放时可以把互为伙伴的空闲块逐级合并。

7.22 常见误区

误区1：order 3表示3个页面

错误：

误区2：整个系统只有一个Buddy

错误。核心空闲链表位于struct zone中，因此是per-Zone Buddy：

误区3：每个空闲页都单独挂在对应链表

错误。一个高阶空闲块通常由首页struct page代表并挂链。

误区4：两个相邻空闲块一定能merge

错误。它们必须是同阶的真正伙伴，并满足Zone、pageblock和页面状态等约束。

误区5：free memory多，高阶分配一定成功

错误。高阶分配要求目标Zone中存在足够大的连续块。

误区6：Reclaim可以解决所有高阶失败

错误。Reclaim增加空闲页数量，但新空闲页仍可能分散。连续性问题通常还需要Compaction和页面迁移配合。

误区7：Compaction会凭空增加空闲内存

错误。Compaction主要搬移可迁移页面、集中空闲空间，不等价于释放更多页面。

误区8：PCP就是Buddy的一条普通链表

不准确。PCP是每CPU快速缓存，页面会在PCP和Zone Buddy之间批量转移，两者的锁、组织和作用范围不同。

误区9：page_private()永远保存Buddy order

错误。struct page字段会在不同生命周期和不同页面用途下复用；只有Buddy空闲块首页这一语境下，才能按本节方式解释。
