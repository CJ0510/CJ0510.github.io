物理内存管理

启动前期物理内存

在Linux启动时，物理内存整个系统是怎么被建立起来的。

比如一块ARM开发板配有1GB DDR，Linux内核也只是一个通用程序，
不能提前指导硬件内存布局，这部分由Bootloader / Firmware通过设备树将
硬件内存信息传递给内核。

当系统正常运行后，物理页主要由Buddy System管理。
这里就有一个问题，像初始化Buddy系统，必须指导物理内存布局；像用Buddy系统初始化物理内存，Buddy还没初始化。
于是又在早期引入memblock，负责Linux启动早期的物理地址区间管理器，同时提供简单的早期内存分配能力。
随后以页为单位管理物理内存。最后进入Buddy System。

内核是以页为基本单位对物理内存进行管理的，每页大小为 4K。一页大小的内存块在内核中用 struct page 结构体来进行管理，struct page 中封装了每页内存块的状态信息，比如：组织结构，使用信息，统计信息，以及与其他结构的关联映射信息等。

而为了快速索引到具体的物理内存页，内核为每个物理页 struct page 结构体定义了一个索引编号：PFN（Page Frame Number）。PFN 与 struct page 是一一对应的关系。

struct page

前面描述的主要是物理内存的分布，后面主要进入怎么从物理内存进入单页。
之前说过，内核以页为单位进行物理内存管理，将物理内存划分为一块一块的物理页，
每个页的大小为4KB。也就是我们的管理方式从region下降到page frame。
为了快速定位具体的物理页，每个物理页都有一个PFN（Page Frame Number），类似数组一样。

假设页大小是 4 KiB，那么每个物理页框中有4096个字节，使用页内偏移指向页内具体的字节。

上面都是从软件角度看的，我们看一下真实的物理内存情况。

上面的图表示的一致性内存访问 UMA（Uniform Memory Access），所有的 CPU 访问内存都要过总线，而且距离都是一样的，由于所有 CPU 对内存的访问距离都是一样的，所以在 UMA 架构下所有 CPU 访问内存的速度都是一样的。这种访问模式称为 SMP（Symmetric multiprocessing），即对称多处理器。
