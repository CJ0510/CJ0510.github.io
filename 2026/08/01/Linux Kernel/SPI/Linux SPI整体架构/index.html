Linux SPI Framework整体架构分析

1 SPI Framework

上一张我们讲解了SPI的物理模型和传输时序图，从这一章开始我们深入分析Linux SPI框架。真个框架如图

看到这张图是不是蒙了？先别急，后面我们会慢慢讲解。你只需要记住，核心就分为三个框架
第一层是设备驱动层(Device Driver)，主要负责设备的功能，简单的理解就是根Soc通信的设备。第二层是SPI Core层，这就是Linux提供的公共框架，负责管理每次的SPI的通信请求。第三层 SPI Controller Driver，负责具体的Soc的SPI硬件。

2 三个核心对象

整个框架里面由三个核心对象，就是软件层抽象的物理世界。分贝是spi_controller、spi_device和spi_driver。其中，spi_controller表示一台 SPI 主控制器，spi_device 表示挂在该控制器上的一个从设备；spi_driver 是对应的从设备的软件驱动。
结构关系：

我们先来看 spi_controller，其在物理层对应Master，源码位置在include/linux/spi/spi.h

我们先不分析源码，先有个概念，它表示一个SPI控制器，SPI控制器就是Soc里面对应的能实现SPI通信的端口。比如一块Soc里面可能SPI0~2三个控制器，那么每一个就对应软件层的一个spi_controller。主要负责产生时钟信号、控制片选CS、数据收发等。

接着看spi_device，对应从机设备。比如你有一个IMU，那么在SPI 控制框架中就被抽象成一个spi_device对象。源码位置在include/linux/spi/spi.h。

有了设备描述还不够，还需要对应的驱动代码，也就是spi_driver，源码也在include/linux/spi/spi.h

5 总结

好了，到这里我们就结束了。Linux SPI框架主要通过分层设计，将SPI设备驱动与SPI控制器硬件实现进行解耦。
整体分为三个部分

  • spi_driver：负责设备功能
  • SPI Core：负责设备管理和数据调度
  • spi_controller driver：负责控制具体的SPI硬件

当设备树创建SPI设备后，Linux通过driver match机制调用设备驱动probe函数，随后设备驱动通过SPI Core提供的接口完成数据传输。
